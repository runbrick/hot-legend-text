# 热血传奇增量游戏 - Electron全文字放置游戏

## Goal

开发一款仿 Progress Quest 模式的增量/放置游戏，主题为热血传奇世界观。全文字呈现，单机运行，本地存储游戏进度。

## What I already know

* 技术栈：Electron
* 语言：中文
* 游戏模式：Progress Quest 风格增量游戏（自动战斗、自动升级、自动获取装备/道具）
* 主题：盛大游戏《热血传奇》的世界架构、道具名称、怪物设定
* 内容约束：不允许自创内容，必须参考热血传奇真实游戏内容
* 类型：全文字游戏（无图形画面）
* 网络：单机，不需要联网
* 存储：本地存储游戏进度（道具、装备、等级等）

## Assumptions (temporary)

* 三大职业可选：战士、法师、道士
* 核心循环：自动战斗 → 获得经验/金币/装备 → 升级 → 更强怪物 → 循环
* 存储方式：localStorage 或 JSON 文件
* Electron 窗口：单一窗口，文字展示区域；支持最小化到系统托盘，托盘时继续运行

## Requirements (evolving)

* 玩家可以创建角色（选择职业：战士/法师/道士，不同初始属性）
* 角色自动战斗、自动升级，战斗日志实时滚动
* **游戏不暂停：升级时属性点累积（玩家回来一次性分配），装备掉落直接入背包（玩家回来逐件查看/更换）**
* **玩家手动选择挂机地图/副本；若战力不足打不过则自动撤退到最近主城**
* **在线挂机：必须运行程序（支持最小化到托盘）才能继续战斗，关闭程序则停止**
* 背包管理：查看、装备/卸下、出售、丢弃道具
* **技能系统：技能随等级自动学会，学会后通过打怪使用升级技能等级（0→1→2→3级，满级3级）**
* 本地存储游戏进度（关闭时自动保存，启动时自动加载）
* 可查看角色属性、装备栏、背包、技能列表
* **角色管理：每台电脑最多3个角色，可删除角色**
* **单实例运行：程序不可多开**

## Decision (ADR-lite)

**Context**: 挂机机制设计
**Decision**: 
- 纯在线挂机：程序运行期间持续战斗，无离线收益计算
- 战斗不暂停：升级属性点累积、装备自动入背包，玩家回来后批量处理
- 地图选择：玩家主动选择挂机副本，战力不足自动撤退
- 技能系统：随等级自动学会，通过战斗使用升级（0-3级）
- 角色槽位：每台电脑最多3个角色，可删除
- 单实例运行
- 死亡复活在主城，不掉装备
- 药水自动消耗，金币买药水
**Consequences**: 
- 需要托盘最小化功能让玩家可以后台挂机
- 无需实现离线进度模拟逻辑
- 属性点需设计"待分配点数"机制
- 技能经验值需独立追踪
- 需要角色选择/管理界面
- 主进程需检测单实例

## Technical Approach

* **框架**: Electron + 原生 HTML/CSS/JS（无 React/Vue，直接 DOM 操作）
* **打包**: electron-builder 打包为 Windows exe
* **存储**: electron-store（本地 JSON 文件，持久化游戏进度）
* **架构**: 
  - 主进程：窗口管理、托盘、存储读写
  - 渲染进程：游戏循环（setInterval）、UI 渲染、玩家交互
  - 游戏数据：热血传奇静态数据（怪物、装备、地图、技能）以 JSON 配置文件存放
* **游戏循环**: setInterval 驱动，每 N 秒执行一次战斗回合
